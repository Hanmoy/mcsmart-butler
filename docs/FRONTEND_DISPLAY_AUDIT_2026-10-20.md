## 2. P0：影响可用性

### P0-1 首次配置浮层在矮屏顶部被裁掉，且无法滚回

**现象**：320×568（iPhone SE / 小屏安卓）下，浮层卡片高 710px，容器 568px，`align-items:center` 使卡片 `top = -71px`。标题「连接你的麦当劳账户」和第一步说明**完全不可见**，且向上无法滚动（`scrollTop` 不能为负）。

**实测**：
```
vp=320x568 → overlayH=568 scrollH=673 card.top=-71 card.bottom=639 topClipped=true
vp=390x844 → overlayH=844 scrollH=844 card.top=109  topClipped=false
```
截图：`.work/audit/overlay-320.png`（首行从"麦麦智能管家使用你自己的…"开始，标题已丢）

**根因**：`public/index.html:523` `.overlay { display:flex; align-items:center; justify-content:center; }` + `:215` `overflow:auto` —— flex 居中 + 溢出滚动是经典冲突：内容超出时上下同时溢出，只有下方可达。

**改法**（二选一，改 1 行）：
- `.overlay { align-items:flex-start; }`（配合现有 `padding:6vh 16px`，视觉几乎无变化）
- 或 `.setup-card { margin:auto; }` 并让 `.overlay` 用 `align-items:flex-start`

**影响**：所有无 Token 的首次使用者，在小屏上第一步就卡住。**这是唯一会阻断流程的显示问题。**

---

### P0-2 战报响应 1.29MB，其中 423KB 是纯重复字段

**实测**（demo 战报，`/api/mcdna`）：
```
HTTP 200  1,286,200 bytes  1.13s
frontSvg 423,041   backSvg 423,879   svg 423,041  ← 与 frontSvg 完全相同
其他元数据 11,415
```

`src/mcdnaReport.ts:253` 同时输出 `frontSvg`、`backSvg` 和 `svg: front.svg`。全仓库检索：**没有任何消费方读取顶层 `svg`**（`src/`、`public/mcdna/panel.js`、`scripts/`、`skill-template/`、`docs/` 均无引用）。

**改法**：删掉 `svg: front.svg`（若需保留兼容，仅 CLI 输出时加）。
**收益**：−423KB（−33%），零功能影响。

**顺带量化**（同一响应）：

| 构成 | 字节 | 占比 |
|---|---|---|
| 正/背面 base64 图片 | 361KB / 387KB | 各自 SVG 的 85.4% / 91.3% |
| 正反面重复的底纹+场景 | 261KB | 全响应 20% |
| SVG 矢量内容（文字/缝线/版式） | 99KB | 7.7% |

图片是体积主因（`bg-cardboard.jpg` 单张 base64 就 191KB，正反面各内嵌一份）。若要再降一个量级，可让渲染用同源 `/mcdna/*.jpg` URL、下载时才内联为 data URI —— 响应可降到 ~110KB（−91%）。但 panel.js 现有安全校验（`panel.js:53` 拒绝非 `data:image/` 的外部引用）需要同步放开同源白名单，属结构性改动，建议单独立项，不与本次显示修复混做。

## 3. P1：明显视觉缺陷

### P1-3 标签页被红+黄双色横条切断（新版专属，首屏最刺眼）

**现象**：活动标签的白底卡片下沿，紧接 `.hero` 的 4px 红色下边框，再紧接 `.stage` 的 3px 黄色上边框 —— 白 → 红 → 黄 → 白，7px 双色横条横穿标签底部。原设计 `border-color:var(--red) var(--red) #fff var(--red)`（`:336`）本意是让活动标签"融入"下方白色内容区，实际被这两条边框破坏。

**实测**：`tabs.bottom=182`，`hero.bottom=186`（含 4px 红边），`stage.y=186`（含 3px 黄边）。
截图：`.work/audit/crop-tabs.png`

**改法**（任选）：
- 给 `.stage` 加 `margin-top:-6px` 并设 `z-index`，让活动标签压住边界；或
- `.hero { border-bottom:0 }` + `.stage { border-top:0 }`，改由标签自身承担分隔；或
- 干脆改成胶囊分段控件（segmented control），不依赖"融入"错觉 —— 与现有 `.seg` 样式统一，最省心。

### P1-4 品牌标吉祥物底部被裁（新版专属）

**现象**：`.brandmark` 是 68px 圆形（`:320`），内含 `svg width=60 height=60` + `margin-top:6px`（`:321`）。可用内高 = 68 − 3×2(border) = 62px，而 60+6 = 66px → 溢出 4px，被 `overflow:hidden` 裁掉，角色领口被切平。
**实测**：`brand.y=14 h=68 bottom=82`；`brandSvg.y=23 h=60 bottom=83`（超出 1px 起裁）。
截图：`.work/audit/crop-brand.png`

**改法**：`margin-top:0` + `svg { width:56px; height:56px }`，或改 `svg { transform:translateY(2px) scale(.92) }`。

### P1-5 单栏页面全宽铺满，正文行宽严重超标

**现象**：只有「双预算精算」用了 `.two-col`（左 420 / 右 644）。「拼单仲裁」「McDNA 战报」「高级数据管理」都是单栏，容器宽 1120px，于是：

| 元素 | 实测宽度 |
|---|---|
| McDNA 的「演示样本 / 真实订单」单选卡 | 各 ~500px |
| 「生成战报」主按钮 | 1080px |
| 提示段落 `.hint`（11px 中文） | **1042px ≈ 95 字/行** |
| 拼单群聊粘贴框 | 1080px |

11px 中文一行 95 字远超可读行宽（40–75 字），配合 P2-9 的低对比度，长说明基本"扫不动"。

**改法**：给单栏内容加阅读宽度约束，最省事的一处改动：
```css
.layout:not(.two-col) > * { max-width:840px; }
.layout:not(.two-col) .hint, .layout:not(.two-col) .note { max-width:64ch; }
```
或把 McDNA 也改成 `.two-col`（左表单 420 / 右战报），与精算页统一 —— 顺带解决 P1-6。

### P1-6 战报双面卡偏小，右侧空出一大片

**现象**：`#mcdnaBox .deck { max-width:720px }`（`:197`），面板宽 1080px → 每张卡只 355px，右侧空 360px。源图 1080×1440，显示比例 0.657，12px 像素字实际约 **7.9px**，卡面文字已接近糊。

**实测**：`imgBox {w:355,h:473}`、`deck {w:720}`、`panel {w:1080}`

**改法**：`deck { max-width:900px }` → 每张 445px（字放大 25%）；或改 `.two-col` 后 `max-width:100%`。

### P1-7 导出工具行混排：两个按钮 + 两个裸文字链接

**现象**：`下载正面 PNG`（30px 高、有边框）、`下载背面 PNG`（同）与 `正面 SVG`、`背面 SVG`（19px 高、无边框、纯文字色）并排。层级混乱，基线不齐，视觉上 SVG 链接像漏排的正文。

**实测**：`#mcdnaPngFront h=30`、`#mcdnaDl h=19`（间距 8px 正常，问题是形态不统一）

**改法**：SVG 下载也做成同规格按钮（或加一个"格式"下拉：PNG / SVG），四件套统一为 30px 高的按钮组。

### P1-8 一行短提示用了整条红色警示块

**现象**：`#mcdnaWarn` 用 `.warn`（红底红字红边）承载 `⚠️ 演示样本不是个人消费记录` 这一行，宽度铺满 1080px。视觉权重远高于信息量，且与真正的错误（`#mcdnaErr`）同级，用户分不清"提示"和"失败"。

**改法**：拆两级 —— 信息级用 chip（`.chip` 或黄色 `.hint`），只有 `#mcdnaErr` 保留红色块。panel.js 里 3 条以内直显、其余折叠的逻辑（`panel.js:92-101`）可保留。

## 4. P2：可读性与一致性

### P2-9 字号偏小（实测，非推测）

| 元素 | 字号 | 位置 |
|---|---|---|
| 标签副标题 `.tab small` | 10.5px | `:334` |
| 单位后缀 `kcal` / `mg` | 10.4px | `:400` |
| 移动端状态胶囊 `.pill` | 10px | `:583` |
| 门店卡元信息 `.smeta` | 10px | `:56` |
| 提示段落 `.hint` / `.note` | 11px | `:97` / `:195` |

建议：辅助文字下限提到 **11.5–12px**，`.smeta` / `.pill` 移动端至少 11px。中文在 10px 下笔画粘连明显。

### P2-10 对比度临界：`--faint` 在页面底色上 4.49:1

| 组合 | 比值 | 判定 |
|---|---|---|
| `--faint #7C725B` on `#FFF8E8`（页面底） | **4.49:1** | 略低于 AA 4.5 ❌ |
| `--faint #7C725B` on `#FFF`（卡片内） | 4.76:1 | 通过 |
| `--muted #6B604B` on `#FFF8E8` | 5.84:1 | 通过 |
| 红 `#D32A1E` on 黄软底 `#FFF1C9` | 4.53:1 | 勉强通过 |

`--faint` 恰好是全部 10–11px 辅助说明的颜色，小字 + 临界对比度是叠加问题。把 `--faint` 压到 `#6F6553`（约 5.3:1）即可整体脱险。
另注：`:9` 还留着旧值 `--faint:#A39B87`（2.76:1），已被 `:298` 覆盖，属死代码。

### P2-11 CSS 大量重复，单文件 211KB

- CSS 45.8KB / 580 行，其中 v1.5 覆盖块（`:293`–`:586`）约 290 行**重写了几乎所有组件**；
- `.tab` / `.tab small` / `.panel` / `.layout` / `.topbar h1` 各出现 **4 次**，`.sol` / `.progress-card .p-indet` / `.brandmark` 各 3 次；
- `:root` 定义两次（`:8` 与 `:297`），旧 token 全为死代码。

不影响功能，但每次改样式都要判断"哪条生效"，是后续 UI 迭代的主要摩擦源。建议：把 v1.5 块合并回原规则（保留最终值），删掉被覆盖的旧声明；CSS 外置为 `public/app.css` 也能让 HTML 首屏少 45KB。

### P2-12 键盘与读屏支持缺口

| 问题 | 实测 |
|---|---|
| 三个标签页是 `div.tab` + click，`tabIndex = -1` | 键盘完全不可达，无法切换功能 |
| 门店卡 `.sbar-item` 同为 `div` + click | 同上 |
| 浮层无 `role="dialog"` / `aria-modal` / 焦点陷阱 / Esc 关闭 | Tab 会跑到背后的页面 |
| 关键异步结果无 `aria-live` | 战报失败、toast、精算结果读屏不播报 |

现有 `aria-live` 只有 2 处（配方预览 `:927`、`:964`）。改造成本很低：标签加 `role="tab" tabindex="0" aria-selected` + 左右方向键；门店卡加 `role="button" tabindex="0"`；`#mcdnaErr` / `#toast` / 结果容器加 `aria-live="polite"`。

### P2-13 触控目标偏小

`高级数据管理` 与 `更换门店` 实测 **25px 高**（低于 32px 建议值），且是移动端常点项。`.secondary-nav button` 与门店卡内按钮的 padding 各加 2–3px 即可。

### P2-14 缺 favicon / meta

`/favicon.ico`、`/apple-touch-icon.png` 均 **404**；无 `<meta name="theme-color">`、无 `color-scheme`、无深色模式。品牌页没有站点图标（标签页空白图标）观感上很掉档。吉祥物 sprite 已在页面里，直接导一个 32×32 PNG/SVG 即可。

### P2-15 `prefers-reduced-motion` 覆盖不全

`:567` 只停了 `.sol` 入场动画与 `.p-indet` 进度条；`.skel` 骨架闪烁（`:553` `animation:sh 1.4s infinite`）与 `.toast` 过渡仍在跑。补两条即可。

### P2-16 空态与结果区不对称

精算页左栏 6 张卡片堆到 927px 高，右栏只有一句"填写预算后点击…"孤零零贴在顶部（`solveKids[1]` 高 76px）。建议把空态做成带吉祥物的 `.state-card`（样式已存在，`:479`）并垂直居中，视觉上左右配平。

## 5. 不建议做的（避免为"丰富"加噪音）

1. **不要为四个页面各配一套插画/装饰**。当前问题不是"不够花"，而是"卡片太多、行太宽、字太小"。加装饰只会放大噪音。
2. **不要引入图标字体或第三方 UI 框架**。页面已有内联 sprite 与统一 token，换框架的收益抵不上回归风险。
3. **不要给战报卡再加展示尺寸档位**（小/中/大切换）。卡面是 540×720 固定版式，缩放只影响清晰度，加开关不解决问题；直接按 P1-6 把默认尺寸调大更有效。

### 9.2 一处取舍说明

### 9.5 追加：标签页"看起来没上下对齐"（用户截图反馈，2026-10-20 04:2x）

**结论：三个标签的盒子几何完全一致，不一致的是"看得见的边界"。**

实测（930×700，`getBoundingClientRect`）：

| 标签 | top | bottom | 高 | 图标 top | 边框 | 阴影 |
|---|---|---|---|---|---|---|
| 未激活 ×2 | 96 | 185.4 | 89.4 | 110 | `2px rgba(0,0,0,0)` | none |
| 激活 | 96 | 185.4 | 89.4 | 110 | `2px rgb(211,42,30)` | `0 3px 0` |

盒子一样，但视觉上差约 7px，原因是两处：

1. 未激活标签的 2px 边框是 `transparent`，**边缘没有可见轮廓**，人眼会把卡片读小一圈；
2. 激活标签的 `box-shadow: 0 3px 0` **只在下方外扩 3px**，只往下长、不对称。

用户截图像素扫描可复现：未激活卡片可见范围 `y=8..74`，激活卡片 `y=8..81`（含阴影），差 7px。

**修法**：三个标签都给同宽的可见描边（几何不变、轮廓一致），激活态改用**内阴影** `inset 0 0 0 1px`，不再向外扩；选中感由白底 + 红边 + 红字承担。

**复验**（像素扫描，两个模式各三个标签）：可见范围全部 `y=8..96`、高 89，完全一致。
